## Architecture

**Tai Qualitative RAG** is a local-first Python research pipeline built to execute reproducible, LLM-assisted thematic analyses of semi-structured qualitative interview transcripts. 

The pipeline canonicalizes varied speaker-turn formats, flags audio-degradation dropout regions, and executes hierarchical Q–A chunking with contextual headers. By leveraging a local, GPU-offloaded **Llama-3.1-8B-Instruct** serving layer, the orchestrator runs multi-worker parallel inference (via `ThreadPoolExecutor`) under strict JSON schema constraints. This offline setup enables high-iteration reliability sweeps without per-token cloud costs or model-drift vulnerabilities.

## The Inductive LLMQ Framework

While standard qualitative RAG architectures rely on deductive coding against pre-existing human codebooks, this engine extends the **LLM-Quotient (LLMQ)** iteration-based reliability framework (Tai et al., 2024) to open, inductive thematic analysis.

- **Stochastic Filtering.** Single-pass LLM open coding is largely stochastic (mean LLMQ ≈ 0.19). To isolate substantive findings from analytical noise, the pipeline executes **N = 20** independent open-coding iterations per chunk.
- **Semantic Clustering.** Open codes are generated from scratch on each iteration. The engine projects these labels into a 768-dimensional embedding space using `nomic-embed-text-v1.5`, performing Durchschnitt average-linkage agglomerative clustering within each chunk to group semantically equivalent codes.
- **Reliability Calculation.** Within-chunk theme recurrence is calculated as the fraction of independent iterations contributing to a cluster. Only themes meeting strict reliability thresholds are rolled up into the final codebook.

## Two-Axis Reliability & Span Stability

To satisfy publication-grade academic scrutiny, the pipeline introduces a two-axis reliability metric that separates thematic agreement from textual citation consistency:

1. **Verdict Recurrence (LLMQ).** Measures whether the model consistently agrees that a particular theme is present within a given chunk of text.
2. **Evidence Span Stability.** Measures the fraction of iterations that cite the exact same verbatim words from the transcript as proof.

Because smaller local models frequently make minor editorial modifications to citations (such as silent pronoun adjustments or stitching non-adjacent clauses), the pipeline implements a **six-stage verbatim recovery cascade**. em-dashes are resolved, whitespace collapsed, and fuzzy-matching ratios calculated to anchor LLM citations back to verifiable, verbatim transcript substrings. This post-processing routine successfully recovers and verifies the integrity of over 96% of evidence quotes.

## Hierarchical Codebook Aggregation

To synthesize thousands of recurrent open-code instances into a publication-ready thematic narrative, the pipeline executes a deterministic, two-level hierarchical clustering sequence:

- **Sub-Theme Clustering.** Agglomerates corpus-wide open codes using Ward-linkage clustering on unit-norm centroids, establishing **K = 30** discrete sub-themes. The LLM is used solely to write structured codebook definitions for each cluster.
- **Top-Theme Merging.** Calculates average centroids for each sub-theme and executes a second Ward-linkage pass to compile **K = 12** top-themes. Ordering is determined by mean LLMQ, ensuring the most robust, convergent findings are presented first.
- **Cross-Pass Sensitivity.** Runs unprimed and minimally scaffolded prompt variants in parallel. The engine performs Jaccard overlap audits on covered chunks to mathematically separate convergent, framing-independent themes from pass-dependent artifacts.
